它要解决什么

工作里的九个真实麻烦

这些问题不是「AI 不够聪明」，而是工具的形状不对。下面每一条都是具体的、可验证的做法差异。

各家模型各有所长，却要在多个网站与客户端之间来回切换、手工复制粘贴。
一个界面内接入并混合调度多家模型与任意自定义 API。
重要问题只问一个模型，怕它漏、怕它错，只能自己反复追问。
混元：多个成员独立作答，独立验收模型收敛出终稿。
多模型输出混在一起，历史记录一团乱，最后还得手工整理。
协作记录有独立会话区与独立记录存放区，与主对话物理隔离。
选模型靠感觉、靠排行榜，别人的评测和自己的任务不是一回事。
论衡：用你自己的真实任务做同题对抗评测，看维度打分与排名。
数据敏感，不想把代码、合同、病历传到云端；本地小模型又不够用。
本地优先：数据落在本机；云端模型可用，但由你决定给谁看。
想让模型真正动手改文件、跑命令，聊天窗口做不到。
桌面 Agent：文件读写 + 命令执行 + 插件工具，带权限分级与审批。
训练或微调要另搭一套环境：装 Python、写脚本、自己配目录。
内置训练页：数据集 → 训练任务 → 实时日志 → 权重导出一条链。
订阅制按席位计费，成本不透明，不知道钱花在哪。
程序内置用量与费用统计；成本只取决于你自己接入的厂商。
换了电脑就要重新配置，工具链锁在某个账号或某台机器上。
便携可移植：便携版可整体拷到任意目录或 U 盘运行。

核心差异一

混元：不是「多开几个模型」，是有角色的协作

多数聚合工具的多模型是「并排各答一份」，最终仍要你自己读、自己判断、自己合并。 混元把这件事做成了角色分工：成员并行处理，另有 1 个独立验收模型 只负责审阅产出、纠正冲突、收敛出一份终稿 —— 它不占成员名额，也不是简单的多数表决。

1 成员模型 A 独立会话 · 独立上下文 · 可用工具 已完成
2 成员模型 B 独立会话 · 独立上下文 · 可用工具 已完成
3 成员模型 C 独立会话 · 独立上下文 · 可用工具 执行中
4 成员模型 D 失败被隔离，原因记录并标出 已降级
并行 → 收敛

验收模型

独立的第 5 个槽位

只审阅成员产出，不只做多数表决：指出遗漏与错误，权衡后给出终稿。

  • 单个成员失败不会拖垮整组
  • 只用成功成员的产出出终稿
  • 验收模型不可用时自动回退到可用模型
  • 可选「协同轮」：把彼此产出喂回再做一轮改进
记录隔离：混元拥有自己的会话列表与记录存放区，普通对话侧栏会过滤掉混元会话。 多模型协作产生的几十条中间产出，不会污染你日常的对话历史。混元参数（成员步数、成员重试、验收步数、验收重试、协同轮） 也不会修改普通对话的步数与重试设置。
核心差异二

论衡：用你自己的任务，决定该用哪个模型

同题多答 → 裁判按维度打分 → 对抗轮互相批判 → 给出排名与融合结论。 默认评估维度为正确性、完整性、可执行性、简洁度，可直接用于模型选型、方案评审， 或对比同一模型在不同提示词下的表现。

正确性 92 / 100
完整性 86 / 100
可执行性 78 / 100
简洁度 64 / 100
上图是打分维度的示意。真实分数来自你自己的任务与裁判模型，不存在「官方榜单」这回事 —— 这也是它的意义：你的场景只有你自己的数据能回答。
1 成员模型 B 84.5 分
2 成员模型 A 81.2 分
3 成员模型 D 76.8 分
4 成员模型 C 71.4 分
对抗轮做什么：让参战模型互相批判并改进自己的答案，再重新打分。 一轮对抗往往比单纯「多问一遍」更能暴露问题，代价是多一次 token 消耗。

扩展

54 个插件工具，按需启停

插件为模型增加工具能力：文件与代码、联网检索、计算与数据处理、智能体协作、模型能力、视觉训练、系统与偏好。 点左侧分类查看该类下的具体工具。

0 个工具
插件体系共注册 55 个插件，其中 54 个暴露工具（另 1 个负责自动重试，不带工具）。 默认开启策略是「除危险级外全部可用」，危险级插件需要你显式打开。
核心差异三

训练：把「用模型」和「训模型」放进同一个程序

多数产品只覆盖其中一段：聊天客户端不做 Agent 工具链，编程 IDE 不做多模型协同评测， 本地运行器不做训练闭环。破晓把三段放在同一套界面与同一份本地数据上。

STEP 01
数据集管理
登记或扫描数据集目录，支持分类、检测、分割、嵌入四类任务； 可按 8 : 1.5 : 0.5 比例一键划分训练 / 验证 / 测试集，种子可复现。
STEP 02
参数配置与训练
默认框架 ultralytics，也可切 timm；轮次、批次、学习率等参数在界面里配置。 训练过程以结构化事件实时回流到日志面板，可随时中止。
STEP 03
评估与导出
训练完成后做指标评估，导出 ONNX / TorchScript 权重， 并可直接在程序内加载模型对新图片推理验证。
训练功能依赖本机 Python 环境，首次使用需安装依赖（设置页可检查并一键安装）。 程序会先探测 Python、torch、CUDA 与已安装的包，把环境信息如实列出来，不会假装准备好了。
核心优势

八件具体的事

  • 01
    不锁定厂商，随时换血
    内置 DeepSeek、OpenAI、Anthropic、Gemini、Ollama 等协议适配，共 18 家提供方； 也可添加任意 OpenAI 兼容 / Anthropic / Gemini / Ollama 协议的自定义服务。新模型上线，填个名字就能用。
  • 02
    任务级容错
    协作与 Agent 运行都自带重试与降级，可配重试次数、退避间隔与 token 预算。 失败被隔离而不是中断整组任务，失败状态在界面上可见。
  • 03
    过程可见、可追溯
    成员状态、重试、失败原因、执行日志都可展开查看，不是黑箱等待。 右侧「运行」面板集中展示运行态与待确认操作。
  • 04
    权限分级 + 审批
    默认「仅工作区」：文件操作限制在你指定的白名单目录内。写盘、执行命令、联网可分别要求审批， 命令白名单与黑名单可自行维护。放开权限永远是显式选择。
  • 05
    成本可核算
    统计页按时间维度看 token 与费用，多模型并行花了多少一目了然， 便于判断「这个问题值不值得上混元」。
  • 06
    为长任务设计的上下文管理
    上下文预算与自动压缩阈值可调，多会话并行时各自的忙碌状态互不干扰。
  • 07
    本地优先与可移植
    便携版可拷到 U 盘运行，程序不依赖安装位置，代码无硬编码盘符。 会话、密钥、统计、训练权重全部落在本机。
  • 08
    克制的界面与可调的动效
    悬浮胶囊顶栏、玄夜 / 宣纸双主题；动效采用非线性曲线逐帧驱动， 并提供应用内动效开关，不受系统「减少动效」一刀切影响。需要无障碍优先时可切回跟随系统。
核心差异四

数据在本机，模型的选择权在你

程序把请求发往你配置的模型服务；不接入云端就完全不联网。 对代码、合同、病历这类不便外发的内容，这一点是很多云端产品给不了的。

会话与消息SQLite
本地数据库文件，含会话、消息、运行记录、指标与协作记录。
API KeysafeStorage
密钥存在本机配置文件，且用操作系统提供的加密能力保护。
用量与费用Metrics
按时间维度记录 token、费用、延迟与调用结果，供成本核算。
训练权重Local files
数据集、训练运行记录与导出权重都保存在本机训练目录。
全部数据位于 %APPDATA%\破晓 Spark Harness\。 备份就是直接复制这个目录；卸载不会删除它，需要清理时手动删即可。 除你主动配置的模型服务外，程序不向任何服务器上传数据。
安全模型

能力越大，闸门越要清楚

一个能读写文件、执行命令的 Agent，如果没有明确的边界就是风险。 这一层是本程序里被设计得最保守的部分。

权限分级Permission modes
仅工作区（默认） —— 文件操作限制在白名单根目录内，写盘与执行命令仍需审批。
完全权限 —— 可访问整块磁盘，写盘与执行命令不再逐次询问。放开权限是敏感操作，需自行评估。
审批与记忆Approval center
写盘、执行命令、联网可分别要求确认：单次允许、本会话允许、始终允许三档。 「始终允许」会被记住，避免重复打扰；也可以随时清空记忆。
命令白 / 黑名单Allow & deny lists
常用安全命令可加入白名单直接放行；危险模式加入黑名单直接拦下。 黑名单的判定在命令真正执行之前。
如实告知的风险Honest limits
「完全权限」下的 JavaScript 执行使用完整运行时，不是沙箱 —— 审批是唯一的闸门。 联网工具对私网地址做了拦截，但域名解析层面的绕过尚未完全封堵。
界面

玄夜与宣纸，两套配色同一套令牌

暗酒红作主色，暖白作文本，深煤灰作层级。浅色主题不是把深色反相，而是重新定义了一套表面与分割线， 保证两个主题下的对比度与层次都成立。

配色令牌Design tokens
背景四级 --bg-0 … --bg-4、 文本四级 --text-0 … --text-3， 主色 #8f303b 在两个主题下保持一致， 另有语义色四组（成功 / 警告 / 错误 / 信息）。
圆角、间距、阴影各有完整层级，界面里不出现「随手写一个 13px」这种值。
动效契约Motion contract
位移与宽度这类需要中途打断的动画，由 JavaScript 逐帧插值驱动，使用非线性贝塞尔曲线 （先快后缓、末段轻微回弹）；纯 CSS 只负责 hover 这类不被打断的过渡。
「界面动效」在应用里只有两档：始终播放（默认）与 跟随系统。默认不跟随系统，是因为 Windows 的「减少动效」 会把所有程序的过渡都压成瞬间完成，而很多人只是关掉了系统动画，并不想让应用变生硬。 （本页多了第三档「完全关闭」，那是网页自己补的便利，不属于应用的能力。）
页面上这两颗按钮是真的可以点的：右上角的月亮 / 太阳切换玄夜与宣纸， 波形按钮切换动效档位 —— 它们调用的就是上面这套令牌与契约。
获取与安装

两种方式，三分钟跑起来

Windows x64 桌面应用，版本 1.0.0。需要自备模型厂商的 API Key，或使用本机 Ollama；训练功能需要本机 Python。

方式一 · 安装包（推荐）Setup · 约 81.8 MB
运行 PoxiaoSparkHarness-Setup-1.0.0.exe。 可自选安装目录，自动创建桌面与开始菜单快捷方式， 无需管理员权限，卸载不会删除你的会话与配置。
方式二 · 便携版（免安装）Portable · 约 111.8 MB
解压便携包，直接运行其中的 PoxiaoSparkHarness.exe。 可整体拷到 U 盘或其他目录，不依赖安装位置。
首次启动
程序会探测本机 Ollama，未安装时首次启动可能慢 15~20 秒，属正常。 不需要本地模型时，到「设置 → 提供方」关闭 Ollama，之后启动明显变快。
配置模型
「设置 → 提供方」打开要用的厂商、填入 API Key，密钥只保存在本机。 接入第三方中转或自建服务时，在该页底部添加自定义 API 并选择协议。
开始工作
在「对话」里直接描述任务；要多个模型互相校验就切到「混元」； 想比较模型表现就切到「论衡」。
关于 SmartScreen：安装包与主程序未做代码签名，首次运行可能出现 Windows 提示， 选择「更多信息 → 仍要运行」即可。这与市面上的个人开发工具情况相同，不是本程序特有的异常。
