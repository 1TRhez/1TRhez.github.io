机器学习实战入门：数据、特征与第一个模型

第一篇我们聊了机器学习的”是什么”，第二篇聊了它的”从哪来”。到了这一篇，该动手了。

但在你打开 Jupyter 敲下第一行 model.fit(X, y) 之前，有个残酷的事实要先说：真实项目里，80% 的时间都花在数据和特征上，而不是模型上。 新手最容易犯的错，就是急着调模型、换算法，结果输入的数据一团糟。

这一篇就专门讲这块最枯燥、也最值钱的部分。

一、 数据：一切的上限

1.1 数据决定了天花板

业界有句话：

数据和特征决定了模型的上限，而算法只是在逼近这个上限。

这句话值得贴在显示器旁边。一个精心清洗的数据集配上一个普通算法，几乎总能打败一个脏数据集配上最先进的模型。所以在动手之前，先问自己三个问题：

  1. 数据够不够？ 样本量太少，任何模型都会过拟合。
  2. 数据干不干净？ 缺失值、异常值、重复行，都是陷阱。
  3. 标签对不对？ 监督学习里，错误标签比没有标签更可怕。

1.2 数据的两种”病”

拿到一份原始数据，第一件事是体检。最常见的两种病是：

病症 表现 常见处理
缺失值 (Missing Value) 某些格子是空的 / NaN 删除、均值填充、中位数填充、模型预测填充
异常值 (Outlier) 明显偏离正常范围 3σ 原则、IQR 四分位距、直接剔除或单独分析

⚠️ 新手最容易踩的坑：看到缺失值就无脑 dropna()。 如果缺失本身带有信息（比如”没填收入”的人往往收入很低），删掉就等于把信号一起扔了。

1.3 一个必须改掉的直觉

传统编程里，我们把数据当”输入”。机器学习里，你得把数据当”教材”——你喂给它什么，它就学成什么样。喂偏了，它就会一本正经地胡说八道。这就是为什么”垃圾进，垃圾出”（Garbage In, Garbage Out）是这行最老的格言。

二、 特征工程：把原材料变成好食材

2.1 什么是特征工程？

特征工程（Feature Engineering），就是把原始数据转换成模型能更好利用的形式的过程。

打个比方：原始数据是刚从菜市场买回来的菜，带着泥、带着根。特征工程就是洗、切、配的过程。同一堆菜，切得好不好，直接决定这顿饭好不好吃。

2.2 数值型特征：缩放是刚需

假设你在预测房价，特征有两个：面积（80~200） 和 房间数（1~5）。

问题来了：面积这个数字天然比房间数大几十倍，很多算法（尤其是基于距离的 KNN、SVM，以及梯度下降类的模型）会误以为面积比房间数重要得多，仅仅因为它数值大。

解决办法是特征缩放（Feature Scaling），最常用的两种：

标准化（Standardization / Z-score） —— 把数据变成均值 0、标准差 1：

$$ z = \frac{x - \mu}{\sigma} $$

归一化（Normalization / Min-Max） —— 把数据压缩到 [0, 1] 区间：

$$ x’ = \frac{x - x_{min}}{x_{max} - x_{min}} $$

怎么选？简单说：数据近似正态分布、有极端值时用标准化；需要固定区间、数据边界明确时用归一化。 不确定就用标准化，它更通用。

⚠️ 关键细节：缩放参数只能从训练集上算。 先用整个数据集算均值和标准差，再划分训练/测试集——这叫数据泄漏（Data Leakage），是初学者最隐蔽的错误之一，会让你在测试集上得到虚假的好成绩。

2.3 类别型特征：不能直接喂数字

机器只认数字，但你的数据里往往有”男/女”、”红/绿/蓝”这种文本。有两种编码方式：

独热编码（One-Hot Encoding）：给每个类别开一列，是就填 1，不是就填 0。

颜色 → 红 绿 蓝
红 1 0 0
绿 0 1 0
蓝 0 0 1

序号编码（Label / Ordinal Encoding）：直接映射成 0, 1, 2。

⚠️ 这里有个大坑：如果类别之间没有大小关系（比如颜色），用序号编码会让模型误以为”蓝 > 绿 > 红”。这时候必须用独热编码。

但如果类别本身有顺序（比如”低/中/高”、”小学/初中/高中/大学”），那序号编码反而是对的，而且更省空间。判断标准就一句话：这个类别能不能排序？

2.4 创造新特征：高手和新手的分水岭

真正拉开差距的，往往是自己造出来的特征。举例：

  • 有”出生日期” → 造出”年龄”、”星座”、”是否周末出生”
  • 有”身高”和”体重” → 造出 BMI
  • 有”点击时间” → 造出”小时”、”是否深夜”、”距上次点击间隔”

模型的数学能力很强，但它不具备常识。它不会自己想到”身高和体重应该结合起来看”。这活必须由你干。

三、 划分数据集：别偷看答案

3.1 为什么要划分？

如果你用全部数据训练，再用同一批数据测试，模型只要把答案背下来就能拿满分——但它遇到新数据就废了。

所以要分家：

数据集 占比 作用
训练集 (Train) 60% ~ 80% 让模型学习
验证集 (Validation) 10% ~ 20% 调超参数、选模型
测试集 (Test) 10% ~ 20% 最终评估，只能看一次

3.2 测试集是”一次性”的

这是很多人不理解的一点：测试集只能用来做最终评估，不能反复拿来调参。

因为你每根据测试集的表现调一次参数，就等于把测试集的信息”泄漏”进了模型。调个几十次，你的模型就变相把测试集也背下来了。这时候那个漂亮的准确率是假的。

要调参，请用验证集。 测试集留到最后，像高考一样，只考一次。

3.3 交叉验证：数据不够时的救命稻草

如果数据量小，划出一大块做验证太浪费，可以用 K 折交叉验证（K-Fold Cross Validation）：

  1. 把训练集切成 K 份（常用 K=5 或 10）
  2. 每次拿 1 份当验证集，其余 K-1 份训练
  3. 重复 K 次，取 K 个结果的平均值

这样每一份数据都当过验证集，评估结果更可靠、更稳定。

这段代码里有三个细节值得反复看：

  3. random_state=42 —— 固定随机种子，让别人（和未来的你）能复现出同样的结果。

五、 评估：别只看准确率

5.1 准确率的陷阱

假设你要做一个”是否患病”的模型，1000 个人里只有 10 个病人。

一个**什么都不学、永远回答”健康”**的废模型，准确率是多少？

$$ \frac{990}{1000} = 99% $$

99% 的准确率，但它一个病人都查不出来。 这就是准确率（Accuracy）最大的问题——在类别不平衡时极具误导性。

5.2 混淆矩阵与四大指标

把预测结果拆成四格，这才是真相：

预测为正 预测为负
实际为正 TP（真阳性） FN（假阴性，漏报）
实际为负 FP（假阳性，误报） TN（真阴性）

由此推出三个更有用的指标：

精确率（Precision） —— 你说是正的里面，有多少真的是正：

$$ Precision = \frac{TP}{TP + FP} $$

召回率（Recall） —— 真正的正例里，你抓出来了多少：

$$ Recall = \frac{TP}{TP + FN} $$

F1 分数 —— 精确率和召回率的调和平均，两者兼顾：

$$ F1 = \frac{2 \times Precision \times Recall}{Precision + Recall} $$

5.3 到底该看哪个？

取决于你更怕哪种错误：

  • 怕漏报（FN） → 看召回率。比如癌症筛查，宁可误报也不能漏掉病人。
  • 怕误报（FP） → 看精确率。比如垃圾邮件拦截，把重要邮件扔进垃圾箱很要命。
  • 两者都重要 → 看 F1。

六、 过拟合与欠拟合：回到那个老问题

第一章我们简单提过这两个坑，现在有了评估指标，可以讲清楚怎么识别和解决。

6.1 怎么判断？

看训练集和验证集的表现差距：

现象 训练集表现 验证集表现 诊断
正常 好 好（略差） ✅ 健康
过拟合 极好 差很多 死记硬背，没学会规律
欠拟合 差 差 模型太简单，没学到东西

6.2 怎么解决？

过拟合（Overfitting） —— 模型太复杂：

  • 增加数据量（最有效，但常常做不到）
  • 正则化（Regularization）：L1 / L2，惩罚过大的参数
  • 早停法（Early Stopping）：验证集误差开始上升就停
  • 降低模型复杂度（减少层数、减少特征）
  • Dropout：神经网络里随机丢弃一部分神经元

欠拟合（Underfitting） —— 模型太简单：

  • 增加模型复杂度
  • 增加有意义的新特征
  • 减少正则化强度
  • 检查是不是数据本身有问题（这一条最容易被忽略）

七、 实战避坑清单

写代码之前，把这七条过一遍，能省你很多个通宵：

  1. 先看数据，再写模型。 df.head()、df.info()、df.describe()，三连起步。
  2. 划分数据集要在任何预处理之前。 顺序错了就是数据泄漏。
  3. 缩放参数（均值/方差）只能从训练集算。
  4. 类别无序用独热，有序用序号。
  5. 测试集只碰一次。 调参用验证集或交叉验证。
  6. 类别不平衡时，别看准确率。 看召回率、F1 或 AUC。
  7. 固定随机种子。 否则你没法判断效果变化是改进带来的还是运气。

八、 下一步

到这里，你已经走完了一个完整项目的闭环：数据 → 特征 → 划分 → 训练 → 评估 → 调优。

下一步该往哪走？两条路：

  • 想走传统机器学习：深入理解具体算法的原理。从线性回归开始，搞懂它到底在最小化什么，然后是决策树的分裂准则、SVM 的核技巧。
  • 想走深度学习：先把神经网络的反向传播推一遍，再上手 PyTorch。别跳过反向传播——它是整个深度学习的发动机。

但不管走哪条路，回来把这一篇的代码自己敲一遍。 看会了和写出来，中间隔着一条河。

结语

这一篇没有炫酷的算法，全是”脏活累活”。

但请相信：当你将来在某个项目上卡住，十有八九问题不在模型，而在数据。 那时候你会想起这一篇。

模型会过时，算法会更迭，但对数据的敬畏心永远不会过时。
